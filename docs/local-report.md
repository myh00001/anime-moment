# 本地看图生成科技节报道

在左上角“照片墙与打印”中勾选“启用本地 AI 报道生成（根据照片）”，点击“应用并保存”。默认关闭，旧设置自动兼容；每次拍照会固定该次任务的开关值。

启用后，Q8量化的SmolVLM2-256M先提取同次拍摄的摄像头原图中可见内容，再由Qwen3-0.6B以非思考模式生成约40～60字的中文短报道。采用分步提示，减少将活动背景当成图片细节的情况。照片和提示词仅发送给板端 `127.0.0.1:8087` 和 `127.0.0.1:8088`，不调用云端 API。报纸右下栏标为“现场报道 · AI生成”；固定作品说明、校徽、日期及活动名称保留。生成失败、超时或返回无效正文时，使用原有固定文案继续生成PDF和打印，不重试提交打印任务。

生成运行在拍照保存线程，不阻塞实时显示线程。每张生成最长等待35秒（含加载）。两个模型串行处理请求，每个进程使用2个CPU线程，服务配置较低优先级和160% CPU上限；闲置5分钟后休眠，下一次使用时重新加载。它不修改现有动漫BPU模型，也不替换相机开机启动服务。

## 在板端准备

系统需要Python3、CMake、GCC/G++、OpenSSL开发库和约3GB可用磁盘空间。模型约1GB，直接保存在板端应用目录的`local-vlm/`，不要加入Git。运行时固定为llama.cpp `b11669`；在S100原系统编译，避免使用要求更新glibc的预编译包。

```bash
python3 scripts/setup_local_report.py --root /home/sunrise/anime-camera --prepare
```

应用目录需要部署`local_report.py`、`run_report_models.py`和更新后的`festival.py`、`festival_settings.py`、`local_display.py`。设置开关启用时会按需启动`anime-report-vlm.service`，不需要将模型服务额外设为开机启动。已准备过模型和可执行文件时，可省略`--prepare`仅安装/刷新用户服务。

模型来自[SmolVLM2-256M](https://huggingface.co/ggml-org/SmolVLM2-256M-Video-Instruct-GGUF)和[Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF)，下载使用HF镜像，权重适用上游许可。运行时来自[llama.cpp](https://github.com/ggml-org/llama.cpp)（MIT），增加了由`FESTIVAL_VLM_SINGLE_VIEW`控制的完整单视图编码，关闭重复图像切片以缩短等待；照片本身不裁剪。源码、模型权重及用户照片均不随本仓库发布。

每张照片目录内的`record.json`记录`ai_report.state`（disabled/generated/fallback）、生成耗时以及成功时的报道正文，供本地排查。没有在网络上发布这些记录。生成内容仍可能有误，提示词要求只描写可见细节，不猜测身份、姓名，不编造采访或奖项。

正文较短且没有提到作品时，补充一句固定的作品事实：“AI动漫拍照让这一刻成为科技节的专属纪念。”

## 本次板端验证

2026-10-23，在1920×1080实时相机继续运行时，用另一张已有照片、关闭提示缓存，完整看图写作实测19.68秒；通过实际照片保存任务、AI生成及PDF-only分发的完整链路实测18.86秒。测试未提交打印。耗时随画面和系统负载变化，35秒预算超时则回退固定文案。

AI只读取同一采集序号的摄像头原图，不读取动漫输出，也不会在原图缺失时改用动漫图。启用AI时原图保存在该次拍摄目录的`original.jpg`，动漫照片仍为`photo.jpg`，用于照片墙及报纸配图。原始帧仅在两个在途推理任务期间保留引用，拍摄时才复制，避免逐帧额外复制。

启用AI报道时，快门完成后显示生成进度、已等待秒数，并锁定手势和空格拍照；排版与提交打印期间保持锁定。任务结束或异常后解锁，只有成功提交打印才显示领取提示，PDF-only不显示领取。

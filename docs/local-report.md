# 本地看图生成科技节报道

在左上角“照片墙与打印”中勾选“启用本地 AI 报道生成（根据照片）”，点击“应用并保存”。默认关闭，旧设置自动兼容；每次拍照会固定该次任务的开关值。

启用后，Q8量化的SmolVLM2-256M先提取同次拍摄的摄像头原图中可见内容，再由Qwen3-0.6B以非思考模式生成约40～60字的中文短报道。采用分步提示，减少将活动背景当成图片细节的情况。默认使用本地 BPU 编码器看原图、CPU 语言模型理解视觉特征，再由 `127.0.0.1:8088` 的本地写作模型输出中文；没有 BPU 资源时保留原 CPU 看图路径（`127.0.0.1:8087`）。不调用云端 API。报纸右下栏标为“现场报道 · AI生成”；固定作品说明、校徽、日期及活动名称保留。生成失败、超时或返回无效正文时，使用原有固定文案继续生成PDF和打印，不重试提交打印任务。

拍摄后定格在该次动漫照片，暂停提交新的动漫推理，等在途任务完成后再启动报道；同时暂停手势扫描。等待动画继续绘制，任务结束（含失败）后恢复实时动漫。AI生成预算35秒（含加载），此前的在途动漫帧等待上限8秒。BPU只负责视觉编码，语言理解和中文写作仍运行在CPU；视觉节点使用4个CPU线程，写作服务使用2个线程及较低优先级。写作模型闲置5分钟休眠，BPU节点按次启动、结束释放。不修改相机开机启动和手动关闭行为。

## 在板端准备

系统需要Python3、CMake、GCC/G++、OpenSSL开发库和约3GB可用磁盘空间。模型约1GB，直接保存在板端应用目录的`local-vlm/`，不要加入Git。运行时固定为llama.cpp `b11669`；在S100原系统编译，避免使用要求更新glibc的预编译包。

```bash
python3 scripts/setup_local_report.py --root /home/sunrise/anime-camera --prepare
```

应用目录需要部署`local_report.py`、`run_report_models.py`、`report_bpu_caption.py`、`report_subject.py`和更新后的`festival.py`、`festival_settings.py`、`local_display.py`。设置开关启用时会按需启动`anime-report-vlm.service`，不需要将模型服务额外设为开机启动。已准备过模型和可执行文件时，可省略`--prepare`仅安装/刷新用户服务。

模型来自[SmolVLM2-256M](https://huggingface.co/ggml-org/SmolVLM2-256M-Video-Instruct-GGUF)和[Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF)，下载使用HF镜像，权重适用上游许可。运行时来自[llama.cpp](https://github.com/ggml-org/llama.cpp)（MIT），增加了由`FESTIVAL_VLM_SINGLE_VIEW`控制的完整单视图编码，关闭重复图像切片以缩短等待；照片本身不裁剪。源码、模型权重及用户照片均不随本仓库发布。

每张照片目录内的`record.json`记录`ai_report.state`（disabled/generated/fallback）、生成耗时以及成功时的报道正文，供本地排查。没有在网络上发布这些记录。生成内容仍可能有误，提示词要求只描写可见细节，不猜测身份、姓名，不编造采访或奖项。

正文较短且没有提到作品时，补充一句固定的作品事实：“AI动漫拍照让这一刻成为科技节的专属纪念。”

## 旧 CPU 路径验证

2026-10-23，在1920×1080实时相机继续运行时，用另一张已有照片、关闭提示缓存，完整看图写作实测19.68秒；通过实际照片保存任务、AI生成及PDF-only分发的完整链路实测18.86秒。测试未提交打印。耗时随画面和系统负载变化，35秒预算超时则回退固定文案。

AI只读取同一采集序号的摄像头原图，不读取动漫输出，也不会在原图缺失时改用动漫图。启用AI时原图保存在该次拍摄目录的`original.jpg`，动漫照片仍为`photo.jpg`，用于照片墙及报纸配图。原始帧仅在两个在途推理任务期间保留引用，拍摄时才复制，避免逐帧额外复制。

启用AI报道时，快门完成后显示生成进度、已等待秒数，并锁定手势和空格拍照；排版与提交打印期间保持锁定。任务结束或异常后解锁，只有成功提交打印才显示领取提示，PDF-only不显示领取。

## S100 BPU 看图路径

先部署以上应用文件，再在板端执行：

```bash
python3 scripts/setup_local_report.py --root /home/sunrise/anime-camera --prepare-bpu
```

安装官方`tros-humble-hobot-llamacpp`，只新增依赖，不升级系统库；下载约166MB的`SigLip_int16_SmolVLM2_256M_Instruct_S100.hbm`，仅适用于S100。复用现有SmolVLM Q8语言权重。检测到节点与HBM后自动启用BPU看图，CPU视觉服务不再同时启动。每次任务使用独立ROS结果话题，等待最终结果后终止节点，避免跨照片串结果。记录中`ai_report.backend`区分实际后端，`vision_seconds`记录看图阶段时间。

提示词提供学校完整名称、2026校园科技节、“做中学科学，实践促创新”、作品名称和互动流程；明确这些是活动背景，不能当成画面已发生的动作。看图结果只描述衣着/姿态，中文译写后补充固定活动纪念语，避免小模型编造采访、奖项、身份和手持物。轻量模型仍可能看错细节。

对同一已有原图，官方BPU节点在动漫运行时18.628秒、定格暂停后6.209秒（两次生成内容不同，仅作单次对照，不代表稳定均值）。定格状态完整照片保存→BPU看图→中文报道→PDF-only流程12.783秒，其中看图3.986秒，AI看图与写作合计11.03秒。所有实验仅在本机处理、未实际提交打印；不包含相机冷启动和打印机出纸。后续真实界面测试见验证结果补充。

2026-10-24真实相机预热后验证：从触发3秒倒计时到PDF-only完成13.418秒，其中AI看图/写作8.13秒、BPU看图阶段4.204秒。处理期间输出帧计数保持31，完成后恢复预览；测试自动恢复原有AI关闭和打印启用设置，没有提交打印。单次样本并非长期均值，图像内容与首次加载会影响耗时。

## 夜间识图改进：500M + 原图主体定位

优先使用官方SmolVLM2-500M（Q8语言模型+BPU视觉编码），资源校验不完整时保留256M回退。安装：

```bash
python3 scripts/setup_local_report.py --root /home/sunrise/anime-camera --prepare-bpu-500m
```

新增约609MB板端模型资源，不上传仓库。`report_subject.py`仅在拍照后复用现有YuNet模型定位最大可见人脸，从同次摄像头原图截取头部及上半身，缩放至编码器512×512输入；原图存档、动漫配图、照片墙和打印取景均保持原样。这样避免衣架服装被误认为人物，也避免宽屏图在官方预处理的左上角填充后主体过小。多个人时只描述最大可见主体，不编造人数。未可靠定位人物时使用中性现场纪念语，不根据背景衣服猜人物或声称画面无人。

小模型对颜色、配饰及未入镜下装仍不可靠，因此报道只保留已观察的上衣类别，再由本地中文写作模型形成短句并补充活动纪念语；不将不确定颜色写入正文。写作结果若新增观察不支持的连衣裙/裙子等类别或下装细节，拒绝该结果、回退固定文案。仍可能发生其他识别错误，不能把语言模型的肯定措辞视作置信度。

2026-10-24隔离同图对照（小样本，非普遍准确率）：近景夹克/正常距离夹克均返回外套，完整AI阶段7.83/6.67秒，BPU看图阶段4.553/4.513秒；人物基本离开画面时使用中性文案1.01秒且不调用BPU推理。此前整图256M曾将夹克误作连衣裙。InternVL3-1B候选虽更大，但在这些图片上仍有衣物细节误判，未采用。全部测试PDF-only，未提交打印。

500M+主体定位的完整保存→AI→PDF-only链路另测8.488秒，其中AI6.79秒、看图4.648秒，不含3秒倒计时、相机预热和实际出纸。部署后AI关闭、未检测到人脸时25秒采样：平均输出8.508FPS（8.233～8.697），CPU84.455%；这是后续实时帧率优化基线，不是不同场景下的可比提升比例。
